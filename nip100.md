NIP-XX: Lightning Network Escrow Events
=====================================

`draft` `optional` `author: [Author]`

This NIP defines event kinds and structure for Lightning Network escrow services.

## Events

### Escrow Agent Registration (30400)
```json
{
  "kind": 30400,
  "content": {
    "version": "1.0.0",
    "pubkey": "<agent_pubkey>",
    "fee_rate": 0.01,
    "min_amount": 1000,
    "max_amount": 1000000,
    "dispute_resolution_policy": "...",
    "supported_currencies": ["BTC"]
  },
  "tags": [
    ["p", "<agent_pubkey>"],
    ["t", "ln-escrow-agent"],
    ["r", "<agent_terms_url>"]
  ]
}
```

### Task Creation (30401)
```json
{
  "kind": 30401,
  "content": {
    "version": "1.0.0",
    "task_id": "<uuid>",
    "description": "...",
    "amount": 100000,
    "payment_hash": "<hash>",
    "escrow_agent": "<agent_pubkey>",
    "deadline": "<unix_timestamp>",
    "requirements": "..."
  },
  "tags": [
    ["p", "<creator_pubkey>"],
    ["p", "<agent_pubkey>"],
    ["t", "ln-escrow-task"],
    ["amount", "100000", "sat"]
  ]
}
```

### Task Acceptance (30402)
```json
{
  "kind": 30402,
  "content": {

    "worker_commitment": "..."
  },
```

### Task Resolution (30403)
```json
{
  "kind": 30403,
  "content": {
    "version": "1.0.0",
    "task_id": "<uuid>",
    "resolution": "settled|disputed|canceled",
    "settlement_proof": "<txid or preimage>",
    "resolution_details": "..."
  },
  "tags": [
    ["e", "<task_event_id>"],
    ["e", "<acceptance_event_id>"],
    ["p", "<creator_pubkey>"],
    ["p", "<worker_pubkey>"],
    ["p", "<agent_pubkey>"],
    ["t", "ln-escrow-resolution"]
  ]
}
```

## Security Considerations

1. All events MUST be signed by their respective actors
2. Payment proofs MUST be verifiable on-chain or via Lightning Network
3. Agents MUST verify task completion before releasing funds
4. Dispute resolution process MUST be clearly defined in agent registration

## Client Behavior

1. Clients SHOULD verify agent signatures and reputation before engagement
2. Clients SHOULD maintain local state of task progression
3. Clients MUST verify payment proofs before accepting resolution

## Implementation Notes

1. Task IDs SHOULD be unique UUIDs
2. Timestamps SHOULD be Unix timestamps in seconds
3. All amounts SHOULD be in satoshis
4. Payment hashes MUST follow Lightning Network specifications
